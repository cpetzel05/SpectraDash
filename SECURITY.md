## Supported versions

Security fixes are normally applied to the latest stable release and, when appropriate, the latest active pre-release.

## Reporting a vulnerability

Do not open a public issue for vulnerabilities involving:

- Remote command execution
- Authentication bypass
- Credential exposure
- API-key leakage
- Unsafe update behavior
- Privilege escalation
- Malicious plugin or theme execution

Use GitHub private vulnerability reporting when enabled. Otherwise, contact the project maintainer privately through the address or contact method listed on the maintainer's GitHub profile.

Include:

- A clear description
- Affected version
- Reproduction steps
- Potential impact
- Suggested mitigation, when known

Do not include real credentials. Use test values.

## Secrets

SpectraDash users should never commit:

- Weather API keys
- Wi-Fi credentials
- Session tokens
- SSH keys
- Private certificates
- Precise home addresses
- Raw support bundles containing personal data
